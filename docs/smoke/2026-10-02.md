## Copy audit and scope of evidence

Reviewed the exercised path at this base revision: `src/checkpoint/open.rs`,
`src/checkpoint/gguf.rs`, `src/gguf/map.rs`, `src/checkpoint/safetensors.rs`,
`src/safetensors/map.rs`, `src/safetensors/manifest.rs` and
`src/safetensors/checkpoint.rs`. Mapping retains file-backed slices; catalog
construction copies metadata only; Safetensors reads headers/index before
mapping and upstream validation. Tensor access returns borrowed slices.
The harness uses fixed stack buffers for positional reads. No whole-checkpoint
payload read/copy was found on this path. Safetensors 0.8.0 upstream
`SafeTensors::deserialize`/`read_metadata` parse metadata and borrow data;
validation checks lengths/ranges without scanning/copying payloads.

Large virtual mappings are expected: approximately 1.90 GB for GGUF and 7.65 GB
for Safetensors. Measured resident growth was at most 6,115,328 bytes for GGUF
and 1,015,808 bytes for Safetensors. Rust live-heap peaks were 217,080 and 256,206
bytes respectively; no checkpoint-sized Rust allocation occurred. These are
observations for these fixtures and host, not universal upper bounds. Snapshot
RSS/native allocations and filesystem cache limitations are documented in the
guide. This does not validate every payload byte or cold-cache throughput.

Negative CLI runs returned exit 1 with the intended diagnostics for missing
arguments, unavailable fixture, deliberately wrong expected dtype, a 1 MiB
resident-growth budget, and a heap budget large enough to conceal the GGUF file.
The synthetic harness tests cover malformed/duplicate expectation rows, wrong
metadata/shard, wrong payload offset, stable borrowed probes and MissingShard.
